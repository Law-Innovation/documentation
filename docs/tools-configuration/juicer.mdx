Typical processing purposes: Unlock additional website features

> This guide explains how to reflect Juicer social feeds in the Consenter Manager. Juicer's embeds have no privacy settings to choose between, so this guide uses a single fixed-behaviour table.
>
> 1. Implement the service as described below.
> 2. Map the implementation in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The mapping is an example, not a guarantee of legal compliance. Verify it against your implementation and current provider documentation.

## At a glance

**Scope.** Juicer (Juicer.io / Juicer Social) social media feeds embedded on the website. Sources were checked on 16 November 2026.

**What the service does in this scope.** Juicer states that it does not track individuals who view Juicer feeds on webpages [S1]. When a feed is embedded, viewers are served static image and video files directly from the social media networks' servers; Juicer does not transfer personal data to the networks, but what the networks record is subject to their privacy policies [S2]. Juicer offers a DPA and SCCs [S3].

> ⚠ **Recommendation — content from social networks.** Juicer itself does not track feed viewers [S1], but media is loaded from the social networks' servers [S2], which receive the visitor's IP address. Load the feed after Consenter consent (or with a click-to-load placeholder) unless your DPO or independent counsel confirms these requests need no consent.

## Step 1 — Implement Juicer

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Unlock additional website features |
| Embed | Juicer embed code or WordPress plugin |
| Loading | After Consenter consent / click-to-load (see ⚠) |
| Contract | Juicer DPA [S3] |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Value to select | Basis and conditions |
|---|---|---|
| Processing purposes | Unlock additional website features | Social feed display |
| Tracking method | Third party tracking (single session, cross-website) | Media requests to social networks [S2] |
| Identifier | IP address | Media requests [S2] |
| Data categories | IP address, Device characteristics | Server requests |
| Legal role of data recipient | Processor | Juicer; social networks as Individual Controllers [S2] |
| Personalisation model | No personalisation | — |
| Maximum storage duration | — | Juicer does not track viewers [S1] |
| Processing location | United States | Juicer and social networks; 18 U.S.C. § 2713 [S4] |

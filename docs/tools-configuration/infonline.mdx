Typical processing purposes: Improve the service, Support marketing analytics

> This guide explains how to implement different privacy configurations for INFOnline Measurement (IVW reach measurement) and how to reflect them in the Consenter Manager. It covers both INFOnline index entries and the legacy entry "Ioam".
>
> 1. Configure the third-party service.
> 2. Map the selected configuration in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The configurations are comparative examples, not guarantees of legal compliance. Verify that the guide matches your product edition, implementation, and current provider documentation.

## At a glance

**Scope.** INFOnline Measurement for websites via the Measurement Manager. INFOnline GmbH is a German company; the legacy IOAM/IOMb tags are replaced by INFOnline Measurement. Sources were checked on 16 November 2026.

**What the service does in this scope.** INFOnline offers two methods: **Census Measurement** (anonymous), which "operates entirely without identification features", and **Pseudonymous Measurement**, which uses client identifiers and requires valid user consent [S1][S2]. INFOnline's own interpretation is that the pseudonymous measurement may only be loaded with active consent under § 25 TDDDG, while the census measurement "may continue to be played out without the user's consent" [S3]. The Measurement Manager integrates with TCF CMPs (IAB vendor 730) or accepts a manual consent string [S3][S4].

**Configurations included.**

| Configuration | Summary |
|---|---|
| Configuration A — Lower risk (no consent, per INFOnline) | Census Measurement only. |
| Configuration B — Medium risk | Census Measurement plus Pseudonymous Measurement after consent. |

**Note on Configuration A.** INFOnline designed the census measurement for use without consent [S3]. As a provider interpretation, document it in your own assessment; if your DPO disagrees, load A after consent as well.

## Step 1 — Configure INFOnline Measurement

| # | Configuration area | Where to configure it | Configuration A — Lower risk | Configuration B — Medium risk |
|---|---|---|---|---|
| 1 | Processing purposes | Operator decision | Improve the service (reach measurement) | Improve the service; Support marketing analytics |
| 2 | Pseudonymous measurement | Measurement Manager [S3] | Disabled | Enabled |
| 3 | Consent transmission | TCF CMP (vendor 730) or manual consent string (`ct`) [S4] | — | Required |
| 4 | Census measurement | Measurement Manager [S2] | Enabled | Enabled |
| 5 | Loading | Consenter / Measurement Manager | Census without consent | Pseudonymous only after consent [S5] |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Configuration A — Lower risk | Configuration B — Medium risk |
|---|---|---|
| Processing purposes | Improve the service | Improve the service, Support marketing analytics |
| Tracking method | No tracking | First party tracking (cross-session) |
| Identifier | No identifier | Device identifiers |
| Data categories | Aggregated site statistics, Browsing and interaction data | Aggregated site statistics, Browsing and interaction data, Device identifiers, Device characteristics, Privacy choices |
| Legal role of data recipient | Processor | Processor |
| Personalisation model | No personalisation | No personalisation |
| Maximum storage duration | Not documented | Not documented |
| Processing location | Germany | Germany |

**Basis.** Census without identifiers [S1][S2]; pseudonymous with client identifiers and consent [S2][S3]. "Privacy choices" is selected in B because the consent string is transmitted to INFOnline [S4]. INFOnline is German-owned; no CLOUD Act flag is applied.

## Privacy-policy follow-up

- INFOnline as processor for IVW reach measurement; census (no identifiers) and pseudonymous measurement (consent); consent transmission.

## Verification checklist

- [ ] Pseudonymous measurement requests only after consent [S5].
- [ ] Valid `ct` variable sent with each request [S5].

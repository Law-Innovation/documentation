<Callout type="info" title="Overview">
This guide explains how to implement different privacy configurations for the Comscore Publisher Tag (Scorecard Research beacon) and how to reflect them in the Consenter Manager. It covers the index entries "comScore" and "Scorecard Research".

1. Configure the third-party service.
2. Map the selected configuration in the Consenter Manager.
3. Update your privacy policy to reflect the actual implementation.

The configurations are comparative examples, not guarantees of legal compliance. Verify that the guide matches your product edition, implementation, and current provider documentation.
</Callout>

## At a glance

**Scope.** The Comscore Publisher Web Page Impression Tag for Media Metrix audience measurement (beacon to `sb.scorecardresearch.com`). Comscore, Inc. is a US company. Sources were checked on 16 November 2026.

**What the service does in this scope.** The tag sends page impression data such as page URL, referrer, browser type and cookie values with each call [S1][S2]. Consent for audience research is communicated with the `cs_ucfr` label (`1` = consent, `0` = no consent, blank = no action); Comscore requires recipients to have an auditable consent trail [S3][S4]. An optional publisher-specific first-party cookie `_scor_uid` is disabled by default; when enabled, it is set only with a consent signal from a CMP or `cs_ucfr=1`, unless the publisher sets `bypassUserConsentRequirementFor1PCookie` [S2][S5].

**Configurations included.**

| Configuration | Summary |
|---|---|
| Configuration A — Higher risk | Publisher tag after consent with `cs_ucfr=1`; first-party cookie disabled (default). |
| Configuration B — Highest risk | As A, plus the first-party `_scor_uid` cookie enabled. |

**No configuration without prior consent.** The tag sends cookie values and is used for cross-publisher audience research [S1][S3]. Do not use the consent-bypass setting for EU visitors; block the tag until consent.

## Step 1 — Configure the Comscore tag

| # | Configuration area | Where to configure it | Configuration A — Higher risk | Configuration B — Highest risk |
|---|---|---|---|---|
| 1 | Processing purposes | Operator decision | Support marketing analytics | Support marketing analytics |
| 2 | Consent label | `cs_ucfr` in the tag (`1` after consent) [S3][S4] | `1` | `1` |
| 3 | First-party cookie | `enableFirstPartyCookie` [S2] | Off (default) | On |
| 4 | Consent bypass | `bypassUserConsentRequirementFor1PCookie` [S2] | Not set | Not set |
| 5 | Loading | Consenter script blocking | After consent | After consent |

## Step 2 — Map the configuration in the Consenter Manager

**Processing location.** Comscore, Inc. is a US company subject to 18 U.S.C. § 2713 [S6].

| Consenter Manager field | Configuration A — Higher risk | Configuration B — Highest risk |
|---|---|---|
| Processing purposes | Support marketing analytics | Support marketing analytics |
| Tracking method | Third party tracking (crosssession, cross-website) | Third party tracking (crosssession, cross-website) |
| Identifier | Device identifiers, IP address | Device identifiers, IP address |
| Data categories | Browsing and interaction data, Device characteristics, Device identifiers, IP address, Privacy choices | Same |
| Legal role of data recipient | Individual Controller | Individual Controller |
| Personalisation model | No personalisation | No personalisation |
| Maximum storage duration | Not documented | Not documented |

**Basis.** Data passed with the tag call [S1]; `cs_ucfr` consent label transmitted to Comscore [S3]; `_scor_uid` [S2][S5]. Comscore uses the data for its own syndicated audience research; verify the controller role against your Comscore agreement.

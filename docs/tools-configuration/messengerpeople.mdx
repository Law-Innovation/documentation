Typical processing purposes: Unlock additional website features, Receive marketing offers

> This guide explains how to reflect the Sinch Engage (formerly MessengerPeople) website widget in the Consenter Manager. The sources do not document configurable privacy settings for the widget, so this guide uses a single fixed-behaviour table.
>
> 1. Implement the service as described below.
> 2. Map the implementation in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The mapping is an example, not a guarantee of legal compliance. Verify it against your implementation and current provider documentation.

## At a glance

**Scope.** The Sinch Engage chat widget, used as an entry point from the website into messenger channels such as WhatsApp (MessengerPeople GmbH, Munich, part of the Sinch group [S1]). Sources were checked on 16 November 2026.

**What the service does in this scope.** Sinch Engage offers widgets as chat entry points on websites [S2]. MessengerPeople documents a way to initialise the chat script only after a third-party cookie tool has given the go-ahead [S3]. Once a visitor clicks through to a messenger, the messenger operator (e.g. WhatsApp/Meta) processes data under its own terms.

> ⚠ **Research gap.** Cookie names and lifetimes of the widget were not found in public documentation. Inspect the widget in the browser before finalising the mapping.

## Step 1 — Implement Sinch Engage

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Unlock additional website features; Receive marketing offers (if used for newsletters via messenger) |
| Loading | Initialise the widget script only after Consenter consent [S3] |
| Messenger channels | Disclose each channel operator (e.g. Meta for WhatsApp) in the privacy policy |
| Contract | DPA with MessengerPeople GmbH / Sinch |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Value to select | Basis and conditions |
|---|---|---|
| Processing purposes | Unlock additional website features | Chat entry point [S2] |
| Tracking method | First party tracking (single session) | Assumed; verify in the browser |
| Identifier | No identifier | Assumed; verify |
| Data categories | Browsing and interaction data, User-provided data | Chat entry |
| Legal role of data recipient | Processor | Provider on behalf of the operator |
| Personalisation model | No personalisation | — |
| Maximum storage duration | Per cookie inspection | Not documented |
| Processing location | Per DPA | German entity of the Swedish Sinch group; check the DPA for US sub-processors |

<Callout type="info" title="Overview">
This guide explains how to reflect SAP Emarsys Web Extend in the Consenter Manager. The sources do not document configurable privacy settings for Web Extend, so this guide uses a single fixed-behaviour table.

1. Implement the service as described below.
2. Map the implementation in the Consenter Manager.
3. Update your privacy policy to reflect the actual implementation.

The mapping is an example, not a guarantee of legal compliance. Verify it against your implementation and current provider documentation.
</Callout>

## At a glance

**Scope.** The Emarsys Web Extend tracking code (`scarab-v2.js` with `ScarabQueue`). Sources were checked on 16 November 2026.

**What the service does in this scope.** Web Extend is the data collection module that tracks visitor interactions on the e-commerce site and feeds them to revenue attribution, the Automation Center, Smart Insight and Predict [S1]. Server-side implementations show the cookies `s`, `cdv`, `xp` and `fc` [S2]. Emarsys email links append parameters including `sc_eh` (an email hash) and `sc_uid`, which connect web activity to a known contact [S1].

**No configuration without prior consent.** Web Extend sets persistent identifiers and builds contact-level behavioural data [S1][S2].

## Step 1 — Implement Emarsys Web Extend

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Receive personalised marketing offers; Personalise the website (recommendations) |
| Loading | Consenter script blocking: load `scarab-v2.js` and push `ScarabQueue` commands only after consent |
| Contact identification | `setEmail` / `setCustomerId` and email link parameters identify contacts [S1] |
| Contract | SAP Emarsys data processing agreement |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Value to select | Basis and conditions |
|---|---|---|
| Processing purposes | Receive personalised marketing offers, Personalise the website | [S1] |
| Tracking method | First party tracking (cross-session) | First-party cookies [S2] |
| Identifier | Device identifiers, Direct identifier | Cookies [S2]; email hash and customer ID [S1] |
| Data categories | Browsing and interaction data, Device identifiers, e-commerce Activity, direct identifier, Users' profiles | Page views, carts, purchases [S1] |
| Legal role of data recipient | Processor | Per SAP Emarsys DPA |
| Personalisation model | Profile based | Predict and recommendations [S1] |
| Maximum storage duration | Per cookie inspection | Not documented in the sources |
| Processing location | Per DPA | SAP is a German group; add the United States if the DPA lists US cloud sub-processors (18 U.S.C. § 2713 [S3]) |

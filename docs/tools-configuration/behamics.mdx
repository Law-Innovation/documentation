<Callout type="info" title="Overview">
This guide explains how to reflect Behamics in the Consenter Manager. Behamics does not document configurable privacy options, so this guide uses a single fixed-behaviour table.

1. Implement the service as described below.
2. Map the implementation in the Consenter Manager.
3. Update your privacy policy to reflect the actual implementation.

The mapping is an example, not a guarantee of legal compliance. Verify it against your implementation and current provider documentation.
</Callout>

## At a glance

**Scope.** Behamics behavioural nudging and session analysis for e-commerce (behamics AG, St. Gallen, Switzerland; Behamics Inc., New York, United States). Sources were checked on 16 November 2026.

**What the service does in this scope.** Behamics analyses live session behaviour and "digital body language" and states that it works "100% anonymized and cookieless" [S1]. It describes itself as a processor and states that pseudonymised data is deleted once the purpose of processing no longer applies [S2].

> ⚠ **Recommendation — "cookieless" does not remove the consent question.** Behamics does not publish which browser storage or device information its script reads. § 25 TDDDG covers any access to information on the device, not only cookies, and the sources do not show that this access is strictly necessary. Load Behamics only after consent unless your DPO or independent counsel confirms a consent-free basis after reviewing the technical implementation.

## Step 1 — Implement Behamics

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Improve the service; Personalise the website (nudges) |
| Tracking | Live session behaviour, stated as cookieless [S1] |
| Loading | Consenter script blocking until consent (see ⚠ recommendation) |
| Contract | Data processing agreement with Behamics [S2] |

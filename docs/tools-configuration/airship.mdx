<Callout type="info" title="Overview">
This guide explains how to implement different privacy configurations for the Airship Web SDK and how to reflect them in the Consenter Manager.

1. Configure the third-party service.
2. Map the selected configuration in the Consenter Manager.
3. Update your privacy policy to reflect the actual implementation.

The configurations are comparative examples, not guarantees of legal compliance. Verify that the guide matches your product edition, implementation, and current provider documentation.
</Callout>

## At a glance

**Scope.** The Airship Web SDK (web push notifications and Web Scenes). Airship Group, Inc. is a US company.

**What the service does in this scope.** The SDK does not send any data to Airship until a channel is created via `sdk.create`, `sdk.register` (push registration) or a Contact registration. Collected data includes the Channel ID, notification opt-in status, Contact ID and the VAPID push subscription; Airship states this data is not used to track users across websites, and that the operator is responsible for collecting consent. Airship states it does not collect browser cookies. Airship operates an EU data centre and a Data Geofencing policy restricting access by US-based personnel for participating EU customers. Web Scenes do not require an opt-in prompt.

**Configurations included.**

| Configuration | Summary |
|---|---|
| Configuration A — Medium risk | Web push only; channel created only on `sdk.register` after consent; EU data centre with Data Geofencing. |
| Configuration B — Higher risk | Web push plus Web Scenes and Contacts (named users); analytics on; EU or US data centre. |

**No configuration without prior consent.** Airship requires the operator to collect consent before using the SDK.

## Step 1 — Configure Airship

| # | Configuration area | Where to configure it | Configuration A — Medium risk | Configuration B — Higher risk |
|---|---|---|---|---|
| 1 | Processing purposes | Operator decision | Receive marketing offers | Receive marketing offers; Receive personalised marketing offers |
| 2 | Channel creation | `sdk.register` / `sdk.create` | `sdk.register` after consent | `sdk.create` after consent |
| 3 | Contacts / named users | Contact API | Not used | Used |
| 4 | Data centre | Project setup; Data Geofencing | EU, geofencing elected | EU or US |

## Step 2 — Map the configuration in the Consenter Manager

**Processing location.** Airship is a US enterprise subject to the US CLOUD Act; the Data Geofencing policy restricts personnel access but does not exclude legal access requests. List the United States in all configurations.

| Consenter Manager field | Configuration A — Medium risk | Configuration B — Higher risk |
|---|---|---|
| Processing purposes | Receive marketing offers | Receive marketing offers, Receive personalised marketing offers |
| Tracking method | First party tracking (cross-session) | First party tracking (cross-session) |
| Identifier | Device identifiers | Device identifiers, Authentication-derived identifiers |
| Data categories | Device identifiers, Device characteristics | Device identifiers, Device characteristics, Browsing and interaction data, Authentication-derived identifiers, Users' profiles |
| Legal role of data recipient | Processor | Processor |
| Personalisation model | No personalisation | Profile based |
| Maximum storage duration | For the duration of the subscription | For the duration of the subscription |
| Processing location | EU; United States | EU or United States; United States |

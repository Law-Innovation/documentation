Typical processing purposes: Improve the service

> This guide explains how to implement Pingdom Real User Monitoring and how to reflect it in the Consenter Manager. Pingdom's synthetic uptime monitoring runs from Pingdom's servers and does not involve website visitors; it needs no entry.
>
> 1. Configure the third-party service.
> 2. Map the configuration in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The configuration is a comparative example, not a guarantee of legal compliance. Verify that the guide matches your product edition, implementation, and current provider documentation.

## At a glance

**Scope.** SolarWinds Pingdom Real User Monitoring (RUM) script. SolarWinds is a US company. Sources were checked on 16 November 2026.

**What the service does in this scope.** The RUM script sends performance data to Pingdom's servers [S1]. RUM uses **local storage** to track visitors, saving a random session ID (`sid`) and the session start time (`sst`) [S2]. Pingdom states that it does not save user IP addresses, uses the IP address only to determine country of origin, and that the session ID is unique per domain, so users cannot be tracked across sites [S1].

**Simplified format.** Pingdom documents no privacy settings to vary (such as storage choice or retention). The guide uses a single fixed-behaviour configuration.

**Consent.** RUM stores information in local storage on the visitor's device [S2]; load the script only after consent.

## Step 1 — Configure Pingdom RUM

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Improve the service |
| Loading | Blocked by Consenter until consent |
| Storage on the device | Local storage: `sid`, `sst` [S2] |
| IP address | Not saved; used for country of origin [S1] |
| Cross-site tracking | Not possible (session ID unique per domain) [S1] |
| Retention | **Not documented** |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Value to select | Basis and conditions |
|---|---|---|
| Processing purposes | Improve the service | Page performance monitoring [S1]. |
| Tracking method | First party tracking (single session) | Random session ID in local storage [S2]. |
| Identifier | Device identifiers | Session ID [S2]. |
| Data categories | Aggregated site statistics, Browsing and interaction data, Device characteristics, Device identifiers, Non-precise location data | Performance data, browser/platform; country derived from IP [S1]. |
| Legal role of data recipient | Processor | Verify against SolarWinds' DPA. |
| Personalisation model | No personalisation | — |
| Maximum storage duration | Not documented | — |
| Processing location | United States | SolarWinds is a US company subject to 18 U.S.C. § 2713 [S3]. |

## Privacy-policy follow-up

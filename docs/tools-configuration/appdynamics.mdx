Typical processing purposes: Improve the service

> This guide explains how to reflect Splunk AppDynamics Browser Real User Monitoring (RUM) in the Consenter Manager. Server-side APM is out of scope. Browser RUM has no visitor-facing privacy settings beyond the switch noted below, so this guide uses a single fixed-behaviour table.
>
> 1. Implement the service as described below.
> 2. Map the implementation in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The mapping is an example, not a guarantee of legal compliance. Verify it against your implementation and current provider documentation.

## At a glance

**Scope.** AppDynamics JavaScript Agent (`adrum`) for Browser RUM. Sources were checked on 16 November 2026.

**What the service does in this scope.** Browser RUM uses short-lived cookies to collect data and correlate events; AppDynamics states they contain no personally identifiable information and are deleted immediately after being read [S1]. `ADRUM_BT` cookies are written by the server-side agent to correlate browser data with business transactions [S2]. By default, the cookie is set on the broadest version of the originating domain [S3]. Setting `window["adrum-disable"] = true` before the agent loads disables browser monitoring [S4].

## Step 1 — Implement AppDynamics Browser RUM

| Configuration area | Fixed behaviour / required action |
|---|---|
| Processing purposes | Improve the service (performance monitoring) |
| Consent gating | Set `window["adrum-disable"] = true` until Consenter consent, or load the agent only after consent [S4] |
| Cookie domain | Optionally restrict to the exact current domain [S3] |
| Contract | Splunk / Cisco DPA |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Value to select | Basis and conditions |
|---|---|---|
| Processing purposes | Improve the service | — |
| Tracking method | First party tracking (single session) | Short-lived cookies deleted after reading [S1] |
| Identifier | No identifier | [S1] |
| Data categories | Aggregated site statistics, Browsing and interaction data, Device characteristics | Timing, Ajax and error data [S2] |
| Legal role of data recipient | Processor | Provider DPA |
| Personalisation model | No personalisation | — |
| Maximum storage duration | Until read (cookies); retention per account | [S1] |
| Processing location | Per controller/EUM region; United States | US enterprise; CLOUD Act [S5] |

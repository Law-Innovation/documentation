Typical processing purposes: Unlock additional website features

> This guide explains how to implement different privacy configurations for the Userlike Messenger and how to reflect them in the Consenter Manager.
>
> 1. Configure the third-party service.
> 2. Map the selected configuration in the Consenter Manager.
> 3. Update your privacy policy to reflect the actual implementation.
>
> The configurations are comparative examples, not guarantees of legal compliance. Verify that the guide matches your product edition, implementation, and current provider documentation.

## At a glance

**Scope.** The Userlike website Messenger (Userlike UG, Cologne, Germany; developed and hosted in Germany [S1]). Sources were checked on 16 November 2026.

**What the service does in this scope.** The Messenger creates the cookie `uslk_umm_{organization-id}_s`, which holds widget and messenger status and the IDs of existing contacts so that they are recognised on later visits; Userlike states the cookie is on the customer's domain and cannot be used by Userlike to track visitors [S2]. Userlike advises loading its JavaScript after consent if you do not consider the cookie technically essential [S2]. Userlike offers a privacy mode and an integrated cookie consent management for the chat [S3][S4].

**Configurations included.**

| Configuration | Summary |
|---|---|
| Configuration A — Medium risk | Messenger loaded after Consenter consent; privacy mode with privacy notice before the chat. |
| Configuration B — Higher risk | Messenger loaded after consent; contacts recognised across visits; contact data (name, email) collected. |

> ⚠ **Recommendation — loading without consent.** Userlike leaves the classification of its cookie to you [S2]. Because it stores contact IDs for recognition on later visits, load the Messenger after consent unless your DPO or independent counsel confirms it is strictly necessary.

## Step 1 — Configure Userlike

| # | Configuration area | Where to configure it | Configuration A — Medium risk | Configuration B — Higher risk |
|---|---|---|---|---|
| 1 | Processing purposes | Operator decision | Unlock additional website features | Unlock additional website features |
| 2 | Loading | Consenter script blocking [S2] | After consent | After consent |
| 3 | Privacy mode / privacy notice | Widget settings [S3] | On | Optional |
| 4 | Contact data | Widget data fields | Not required | Name, email |

## Step 2 — Map the configuration in the Consenter Manager

| Consenter Manager field | Configuration A — Medium risk | Configuration B — Higher risk |
|---|---|---|
| Processing purposes | Unlock additional website features | Unlock additional website features |
| Tracking method | First party tracking (cross-session) | First party tracking (cross-session) |
| Identifier | Device identifiers | Device identifiers, Direct identifier |
| Data categories | Browsing and interaction data, Device identifiers, User-provided data | As A, plus direct identifier |
| Legal role of data recipient | Processor | Processor |
| Personalisation model | No personalisation | No personalisation |
| Maximum storage duration | Per cookie inspection | Per cookie inspection |
| Processing location | Germany [S1] | Germany [S1] |

**Basis.** Cookie [S2]; German hosting [S1], so no CLOUD Act flag unless the DPA lists US sub-processors.
